# 语境表达规划

2026-10-20 状态：根据用户试听反馈，停止自动歌词语义路线，不在桌面工作流启用，也不再配置语义服务或扩展“情绪→参数”配方。已有导入试验和校验器保留供历史追溯。后续复用显式结构、带来源的方法、字词定位和人工局部选择，服务由用户选择的风格。下文 API 示例记录保留的实验工具，不代表推荐的自动调声流程。

这是可选的后端入口：复用已有乐谱与原文，按结构和词句位置检索带来源的方法，提出多个演唱意图候选。另有不绑定厂商的整段语义响应接口。内置路径不配置语义模型，不合成音频、不选择声库、不写入表达参数。原有工程与音频输出仍分别工作。

从应用根目录用自带Python运行生成模块，不直接运行src内文件：

```powershell
& '.\dependencies\vocal2midi\python\python.exe' -B '.\context_workflow.py' prepare --job 'C:\BVWA\jobs\example'
& '.\dependencies\vocal2midi\python\python.exe' -B '.\context_workflow.py' propose --job 'C:\BVWA\jobs\example' --goal '首句克制，并提供一个更明确的替代唱法'
& '.\dependencies\vocal2midi\python\python.exe' -B '.\context_workflow.py' export --job 'C:\BVWA\jobs\example'
```

请替换示例任务路径。需要已有的各声部USTX，无需重跑ASR或MIDI。也可通过project_exports.py --job TASK --context接入普通导出，或在有效请求中设置context_enabled=true。context_plan可指定已有计划；相对路径在任务内解析。命令行覆盖选项不会重写原request.json。本轮尚未增加界面控件。

prepare在context/plan.json建立可编辑的空草稿，不自动覆盖已有计划。乐谱、歌词、明确词范围或时段证据变化后，旧计划会因证据不匹配停止应用，不自动把手势挪到其他音符。显式使用prepare --refresh-draft会先备份旧计划，再生成空草稿。

证据保留任务歌词原文、Unicode码点范围、当前音符与稳定ID、经核实的音节时段及重叠关联。只有完整歌词序列一致时才确认字面关联；不能从拼音或罗马音猜回原文。无法判断的关联明确保留未知。连字符和USTX的+~可继承已确认的前一单元，单独+不冒充可靠延音。

字不冒充词。可用--words FILE传入按声部分组的明确词范围，例如{"vocals":[{"span":[0,2],"source":"manual"}]}。范围从0开始，按Unicode码点计数，右端不含。prepare把输入保存在context/word-spans.json，后续export继续使用。API也可在有效请求中提供context_word_spans。

仅当quality.json本身及当前USTX的哈希都与生产回执一致时，才使用其中音节时段。手工修改或旧工程仍可提供当前乐谱事实，但不采信未经核实的声学时段。时刻换算包含USTX片段偏移、分辨率及速度变化。

默认计划包含schema_version=1、kind=bvwa.context-plan、当前evidence_ids、空candidates和selected_candidate=null。每个候选具有唯一短ID、intent和gestures；手势引用voice、真实note_ids、onset/sustain/release阶段及文字direction，可加rationale。请引用实际证据中的ID。过时证据、未知音符、重复ID、未知字段、直接SV参数和概率字段会被拒绝。校验通过只证明契约有效，不证明语义判断正确。

exports/context保存每声部证据、已校验计划快照和preview.json。预览保留全部候选、选择结果，以及可用时经回执核实的基线SVP引用。状态明确为advisory_only、adapter_not_implemented、project_written=false、audio_rendered=false。它是候选计划产物，不是新调好的SVP；声库手势适配器留待后续实施。

这些产物有独立回执和文件索引。计划、证据、基线或语境模块变化只使语境产物失效；修改计划不改变基础工程签名或MIDI推理输入。语境阶段失败/取消后已提交的基础输出保留，可继续恢复；重新生成会保护手工改过的语境产物。此模块不修改原参数、原点、幅度、长音、音高、未知参数通道及已保留的人工调声。

声部选择变化后，旧语境证据的回执和文件索引标为不再活动，原文件作为历史保留；重建索引不会把失活回执恢复成当前产物。关闭语境导出时，不导入其可选模块。

功能与契约测试使用隔离任务和合成乐谱，不能代替真实语境准确率、声学指标或试听反馈。

## 结构、方法检索与不同唱法

propose保存独立的context/proposal-input.json、context/proposal.json、严格的context/plan.json，并通过原有回执机制保存exports/context下的快照。提案包含各声部结构、局部方法匹配依据。可用--semantic-response FILE导入明确提供的JSON解释；--words FILE用于prepare和propose，提案验证通过后才提交词范围。

对相同的程序生成计划重复propose会复用有效输出；省略--goal或--semantic-response时沿用已保存输入。手工编辑的非空计划需显式--refresh-draft才能备份后替换，外部--plan始终只读。preparing/ready记录区分写入计划前后的中断；计划在处理中出现新手工编辑时会停止覆盖。重新导出手工选择或修改后的严格计划，仍保留原提案中的其他候选。

结构分析保留原文码点范围、段落、短语、复现关系、明确的词位置和乐谱休止/音长事实。没有分词依据时不把每个字称为词。否定、转折、条件与对象词只记作表层线索，其语义作用域保持未知；长音/休止阈值是已声明的规则选择，不是情绪标签。反讽、段落功能、吸气和人物关系仍需其他证据。

方法卡保留来源ID/链接、原作者场景、简短转述、相反选择与限制。目前14张卡片全部保留：5张正文方法卡参与检索，9张因为场景条件不足或仅有索引证据而禁用。禁用自动检索不评价这些风格的音乐价值。匹配分数只说明结构依据，不代表概率或音乐优劣；自由文本目标不影响排序。跨语言、跨声库迁移明确保留条件。音素时值、音高纹理、声库模式和混音均只是文字建议，本流程不自动应用。

规划器保留不同意图，默认不选中候选。用户目标、结构假设、来源观察与语义响应中的主张分别标记。离线基线不把自由文本目标解析成手势，明确记录goal_not_used_for_gestures并保留用户选择；否定或其他词语里的单字命中不当作语义证据。休止不等于吸气，复现句也不必逐次加强。未知的文字/音符关联不生成猜测的语义手势；覆盖限制和待确认事项会保留。不会用数学拟合否定参考工程的个性。

## 可选语义接口

context_semantics提供Python callable接口，没有隐式HTTP客户端、端点、凭据或模型下载，也不把中文ASR模型当作通用规划器。没有provider时明确记录未推理；调用方显式接入provider时需负责其执行方式与授权。歌词作为引用数据，与系统指令和用户目标分开。`lyric_data.text`和`structure`中的短语、段落、线索文本都可能含不可信歌词；只清空`lyric_data`不能移除整个请求里的歌词。provider失败只保留异常类型，不保存可能含私有歌词或凭据的错误消息。

导入的JSON响应必须引用当前证据版本，并提供有长度限制的解释、原文范围/逐字引用、焦点角色、意图、依据、替代解释与未知项。内容指纹检查会拒绝“修改文字/音符却沿用旧ID”的证据；来源真实性仍由生产回执判断。响应中的provider名称/型号只是声明，不证明实际调用过该模型。仅绑定证据的导入响应，其目标来源保持未知，不能当作满足另一个当前目标。过时引用、无效范围、未知字段、直接参数数组和概率字段会被拒绝。格式和关联校验不证明解释正确；手工响应是功能夹具，不是模型评测。

可选provider失败时可保留结构候选并记录失败；显式导入的非法响应会报错。内置CLI不将私有歌词上传到远程服务。数值声库适配仍需与乐谱、声库和版本相符的有效配置；诗岸PLUS的历史试验不等于本轮重新校准。

语义请求包上限仍为512 KiB。有效乐谱超过这个可选接口的上限时不调用provider，保留离线规划，并明确记录request.status=request_unavailable，不把截断内容冒充完整语境。导入响应仍需独立校验当前证据；局部范围、手势及音符数量限制会记录为部分覆盖或局部子集。

任务JSON记录上限为8 MiB。提案会按Windows换行计入实际容量并预留提交元数据空间，超过上限时在替换已有输入或计划前报错，避免写出下次无法读取、无法续做的记录。
