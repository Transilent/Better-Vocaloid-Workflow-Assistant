# 可选视频合成与分离路径

[English](OptionalWorkflows.en.md) | [简体中文](OptionalWorkflows.zh-CN.md)

## 合并后的实验演唱风格

调音工作流当前只列出 **柔和〔实验〕** 与 **明亮有力〔实验〕**，默认保留原表现。整轨方式选择一个风格；不同非重叠时间片段可分别选择其中一种，两者都不在已有风格候选上叠加。总强度与 `onset`、`sustain`、`connection`、`release` 四个 `0…1` 分段系数共同缩放局部变化：`onset`、`release` 调节音色和附加音高，`sustain` 仅调节音色，`connection` 仅调节局部音高衔接。关闭附加局部音高只停用音高动作。短于 160 ms 的音符、rap/BR、静音及重叠音符不添加新动作；已有非线性曲线、颤音状态与未知内容保留。

时间片段方式显示所选实际目标轨的音符，可横向框选时间，并按非重叠片段分别保存风格、总强度、四段系数和音高开关。片段列表非空时只处理片段范围，区外保留主参数来源处理后的风格原线；参考、校准或沿用参数仍按所选轨整轨处理。片段最多 128 个，短于 25 ms 的选区无效。钢琴卷帘只显示音符和选择范围，不编辑音符、音节、歌词、节奏或声库。

`style_regions` 只属于当前输入会话的执行选项，不写入通用偏好；换输入会清空片段，恢复记录也要求输入 SHA 匹配。旧六个标识仍可从已有任务和旧命令行记录读取。打开旧工程或旧候选文件不会自动改写文件；界面把旧 ID 显示为 `gentle` 或 `bold` 的合并卡，用户随后保存偏好或重新生成时使用新 ID。旧音高默认仍按原标识解释。公开选项、分段记录和试听边界见[实验演唱风格](StylePresets.zh-CN.md)。

## 视频合成

**视频合成**是独立的侧栏页面，选择原视频、Mixdown 和成品保存位置即可运行，无需先创建音乐任务。已有成品可直接进入发布工作流，不必合成。

自动对齐通过共同的能量／节奏变化估计偏移，匹配不明确时会拒绝继续。录音缺少足够共同内容时，请使用手动偏移：正数延后 Mixdown，负数提前。
生成前在 **生成前音频对齐** 区域点击 **分析音频对齐**：助手比较原视频首条音轨与 Mixdown 的能量／节奏变化，报告建议偏移和可信状态。结果可信时，可点 **使用建议偏移** 将其转入手动偏移；勾选自动对齐时，经过校验的生成前分析也可在合成时复用。匹配不明确、证据不足或任一输入发生变化时，结果不会自动采用；请试听 Mixdown 后手动填写。手动偏移始终可用。可选的双遍响度处理以 −14 LUFS 为目标。原视频画面直接复制，原音轨被替换；新音频按视频长度补齐或裁剪，保留完整视频。

合成不会覆盖输入和已有成品，取消时会清理临时输出。检查结果后，可用 **将成品带入发布工作流** 填入视频路径，不会自动上传。合成期间阻止安装更新和清理缓存。工作文件位于可清理的 `cache/video-mixdown` 中。分析工作位于 `cache/video-alignment`；它只比较能量起伏，不判断音乐内容，也不替代试听。

## 减少主唱的串行处理

内置 Karaoke 2 仍先接收总人声，再拆主唱和和声。安装可选 BS-RoFormer 组件后，可选择两种路径：

| 路径 | 模型输入 | 最终三轨 |
| --- | --- | --- |
| 默认串行 | 原曲 → HQ3 总人声；总人声 → karaoke 模型 | 主唱、求差得到的和声、HQ3 伴奏 |
| 原曲独立提取主唱，实验 | HQ3 和 BS karaoke 分别接收原曲 | BS 主唱、HQ3 总人声减 BS 主唱、HQ3 伴奏 |

两种方案都需要**两次模型推理**。实验路径将主唱最多经过的模型次数由两次减为一次，还不是单个模型直接预测三个声部。权重保持不变，中日文使用相同分离方式，后续 ASR 按语言选择。

独立预测求差能够保持时间和采样数一致，三轨相加也能还原原曲；但两个模型判断不一致时，误差可能留在和声中。相加误差小只能证明计算一致，不能证明分离更准确。请分别试听主唱和和声后选择，默认路径暂时保留。

已检查的 [BS karaoke 权重](https://huggingface.co/becruily/bs-roformer-karaoke)声明的是 Vocals／Instrumental 两路输出。[Karaoke 2 模型说明](https://huggingface.co/musetric/uvr-mdxnet-kara2-onnx)要求使用已分离人声，因此没有为它提供原曲独立提取入口。目前尚未接入经过验证、明确输出主唱／和声／伴奏的单次三轨权重。后续适配需先核对声部含义、归一化、声道及精确采样数。

## 自动检查主唱串音

自动分离主唱与和声后，助手会检查和声中是否仍有与主唱高度相关、相位一致的重复成分，并把符合条件的频段归回主唱。这一步使用已有的信号处理库，不增加模型权重或神经网络分离层。用户导入的分轨保持原样。

检查保持音频采样数、双声道和两轨叠加的总人声，不按音量大小交换声部，也不会把只有和声的段落直接当成主唱。程序按短块处理，并保持统一的分析网格，避免块边界改变长音。方法和影响区间写入 `separation-report.json`；其中的能量比例不代表分离准确率。

这项检查不能保证完全消除串音。带延迟或音色差异较大的残留可能保留；人为制作的同相同音叠唱，也可能与复制泄漏难以区分。打开已有任务不会直接改写分轨；重新处理时才会使用新的流程。

## 实测声库拟合

校准实验详见[参考演唱参数](ReferenceDynamics.zh-CN.md#声库响应校准拟合开发实验)。助手准备一个七轨试音工程，用户在 SV 中触发一次分轨导出后，自动收集、校验七份 WAV 并拟合另存工程，不增加神经网络权重。校准绑定当前乐谱，与默认参考映射分开，默认关闭。SV 的 Bounce 操作仍需人工触发。
