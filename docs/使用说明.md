# Better Vocaloid Workflow Assistant 使用说明

双击 **启动助手.bat**（原来的 `.cmd` 也可用），输入 BV 号或 B站链接，点击 **开始处理**。
默认直接调用模型完成下载、分离和 MIDI 提取，不需要打开 UVR、SpectraLayers 或 Vocal2Midi 的界面。

## 处理方式

| 方式 | 处理过程 | 输出 |
| --- | --- | --- |
| 模型全自动：主唱 / 和声 | Inst HQ 3 分离人声与伴奏，Karaoke 2 拆分人声，两个声部分别调用 Vocal2Midi | 主唱、和声、伴奏、双轨 MIDI |
| 软件分离：导入 SpectraLayers 分轨 | 选择已导出的主唱、和声、伴奏完整 WAV，自动识别并合并 | 双轨 MIDI、统一格式的音频 |
| 原版：合并人声单轨 | 模型分离人声和伴奏，识别合并人声 | 单声部 MIDI |

模型通过 ONNX Runtime / DirectML 在本机运行，不依赖窗口、截图或鼠标操作。
MDX 使用 50% 窗口重叠、正负极性预测平均，以减少部分分离伪影。
这不能保证优于 SpectraLayers。模型按主唱/和声的音乐角色分离，不能按歌姬身份识别，仍可能串音或分配有误。
“精细提取（较慢）”使用 16 步 GAME 推理，关闭后为 8 步；准确率仍取决于音频与模型。

## 续跑与重做

**继续上次任务**沿用原任务的模式、语言、歌词和参数，继续未完成步骤。
若主唱已经提取完成，和声阶段取消，续跑会复用主唱。

**重做上次分离 / MIDI**按界面当前选项创建新任务，复用已下载的视频、原音频和简介。
适合更换分离方式、歌词或提取精度；旧结果保留，便于比较。

声部结果记录音频、参数和输出校验值。输入或助手内 Vocal2Midi 设置变化、MIDI 损坏时会重新提取；
合并文件损坏时可复用两个已完成的声部重新合并。
取消会结束整个推理进程树，正在计算的模型最多等待 30 秒后强制结束。

## 歌词与音准

主唱和和声可分别提供参考歌词，只粘贴歌词；空格、标点和换行自动去除。
不要粘贴完整简介或 STAFF。和声歌词留空时独立识别，不套用主唱歌词。
取消“识别歌词并写入 MIDI”可只提取音符。
没有可用歌词对齐的片段，Vocal2Midi 会回退为纯音符提取。
静音和声会输出空和声轨并提示，不会使整个任务失败。
分离伪影会影响自动识别。已知歌词时，推荐分别填入主唱和和声参考歌词；
本版保留两种分离方案，请试听并在调音软件内核对音准。

`midi/需要核对的音符.csv` 标记极短音符、至少八度的跳进，并附秒数位置。
它们也可能是正确装饰音或旋律，程序不会自动修改音高。

## 输出

每个任务保存在 `jobs/BV号_时间/`：

| 文件 | 用途 |
| --- | --- |
| `midi/voices.mid` | Lead Vocal / Backing Vocal 两个声部轨；另含无音符的速度元数据轨 |
| `midi/lead/lead.mid`、`midi/backing/backing.mid` | 可分别导入的主唱、和声 MIDI；同目录有 CSV/TXT 和报告 |
| `midi/vocals.mid` | 单轨模式输出 |
| `midi/需要核对的音符.csv` | 双轨模式音符核对提示 |
| `audio/lead.wav`、`audio/backing.wav` | 主唱、和声 |
| `audio/instrumental.wav`、`audio/vocals.wav` | 伴奏、合并人声 |
| `audio/source.wav`、`video/source.mp4` | 原音频、原视频 |
| `cover.jpg` | 本家在 B站展示的原始封面；旧任务可能保留历史截图，请在发布页重新获取 |
| `original-cover.jpg` / `.png` / `.webp` | 原始封面文件，旁边的 JSON 记录来源和校验值 |
| `发布简介草稿.txt` | 输入视频及引用原曲的来源、作者、歌姬与 STAFF 草稿 |
| `status.json`、各阶段日志和报告 | 进度、参数及失败原因 |

音频统一为 44,100Hz、双声道、32 位浮点 WAV，不分别调整音量，不截去前奏或开头静音。
MIDI 使用 120 BPM 换算时间、关闭量化，120 不代表已检测到歌曲 BPM。
在 SV 调整工程 BPM 时，需要保持音符在实际秒数上的位置。

## 导入 SpectraLayers

1. “音频分离歌曲”仅勾选人声和其他，质量选高。
2. 选中人声图层，用“音频分离合唱”得到主人声和伴唱人声。
3. 导出所有图层，范围选**从项目开始**，格式可选 32bit float。
4. 在助手导入模式依次选择“主人声”“伴唱人声”“其他”，对应主唱、和声、伴奏。

三个文件必须来自同一个原视频且保留完整时间轴。
程序拒绝长度不符的文件；48kHz 或单声道音频会自动转换。
长度检查不能识别一个被整体平移但总长度不变的文件。

## 命令行复用

在助手目录打开 PowerShell，直接分离本地 WAV / MP3 / MP4，无需运行 MIDI：

```powershell
& '.\dependencies\vocal2midi\python\python.exe' -B .\separate_audio.py --input '你的音频完整路径.wav' --output '.\本地分离结果'
```

输出文件夹必须为空。加 `--single` 可仅分离合并人声和伴奏。
在输出文件夹创建 `cancel.flag` 可取消，保留已完成文件。

完整 BV 流程：

```powershell
& '.\dependencies\vocal2midi\python\python.exe' -B .\pipeline.py --source 你的BV号 --voice-mode dual
# 仅音符：加 --notes-only
# 精度：--midi-steps 8 / 16 / 32
# 继续任务：--job '任务完整路径'
# 仅运行到分离：--until separation
```

## 配置与范围

运行依赖已集中在 BVWA 文件夹内，`config.json` 使用相对路径。Inst HQ 3 位于 `dependencies/models`，Karaoke 2 位于 `models`。
可将 `separation_device` 或 `midi_device` 改为 `cpu` 排查显卡问题。
助手内置 Vocal2Midi 的 Python、模型、设置和运行代码，保留原许可证；不会修改原软件。
运行时临时文件和缓存位于助手的 `cache`。历史任务中的已知旧安装路径会自动映射到目录内依赖，不改变旧任务参数或已经完成的 MIDI 校验值。
启动失败时保留提示，详情见 `launcher.log`。

本版包含下载、模型分离、软件分轨导入、MIDI、封面和发布资料，以及创作中心上传填写脚本。
调音、将 mixdown 对齐合并到原视频目前仍由人完成，再把成品 MP4 交给发布模块。
最终发布在浏览器由人点击。

## 发布准备 / 上传

1. 重新打开助手，切换到 **发布准备 / 上传**。
2. 选择来源任务，或输入成品对应的 BV 并点 **读取 BV 资料及原视频**。
   这里只下载资料和原视频，不重新分离或提取 MIDI。不要沿用另一首歌的来源任务。
3. 选择已经调音、剪辑完成的成品视频。选段视频可比本家短。
4. 每次填写翻唱歌姬、调音署名；点 **套用【歌姬翻唱】歌名**。
   两项可留空，歌姬为空时标题为 `【翻唱】歌名`。标题也可直接编辑；手写模板里的 XX 必须替换。
   两个平台可分别编辑标题、简介。
5. 简介保留输入视频以及引用原曲的 BV、作者、歌姬、STAFF 原文。
   本次署名通过按钮加入简介。请核对原文中的“我”仍属于被引用的本家作者。
6. 封面默认选择 **本家原始封面**，点 **获取 / 预览** 从 BV 对应的视频资料中获取原图。
   原图指本家在 B站展示的封面，不是视频画面。下载失败会提示，不会自动改用截图。
   也可主动选择 **视频画面截图（可选）** 并指定秒数，或选择 JPG/PNG/WebP 图片。
   B站的4:3封面自动补黑边，保留完整图片；16:9原图按原比例使用。
   发布包内 `cover.jpg` 保留源图，`cover-bilibili-4-3.jpg` 是补边后的4:3文件。
   其他比例的手选图片也会分别适配4:3、16:9；已经相同比例的图片不重新压缩。
   点 **生成发布包**，素材和文稿保存在 `publish-packages/BV号_时间/`。
7. 初次使用，点击对应平台的 **登录 / 更换账号**，在专用 Chrome 中登录，登录后关闭窗口。
   后续使用独立浏览器目录中的会话，不读取你平时浏览器的个人资料目录。
8. 点 **上传所选平台** 一次启动已勾选的平台，也可分别点 **上传填写，等待人工发布**。
   程序选择视频、填写标题和简介，等待视频上传完成后再设置封面，避免首次上传时封面控件尚未就绪。
   B站会关闭双比例同步，分别上传两张封面并重置缩放，核对实际画布后才保存。
9. 浏览器保持打开。核对封面、上传/转码、分区、标签、原创/转载及其他必填项，再手动发布。

助手会保存最近生成的发布包和手填资料。也可点 **载入发布包…** 恢复其他发布包。
网页任务仍打开时，点 **继续填写** 可重新写入发布包的标题、简介和封面，不重传视频。
修改助手中的资料后先重新生成发布包，再点 **继续填写**。新包的成品文件和校验值必须与已上传视频相同。
因此可以替换错误封面、修改署名和简介；换成另一份成品视频则要重新上传。
网页已手工修改的这三项会被发布包内容覆盖。
浏览器已关闭时，继续填写不可用；重新上传需要再次选择视频。

文字过长会提示编辑，不自动截断标题或 STAFF。视频、封面或草稿改过后需要重新生成发布包。
发布包记录文件校验值，防止把生成后被替换的成品作为旧资料上传。
资料变化检查和文件验证不等于对歌姬、歌词或来源的人工审核。

程序以页面控件操作，使用 [Playwright 的文件上传接口](https://playwright.dev/python/docs/input#upload-files)，
无需截图、鼠标坐标或 computer use。页面改版、找不到唯一控件、封面未确认或上传未完成时，
显示需要人工处理并保留浏览器，不把选择文件误报为上传成功，也不重复自动提交视频。
网页选择器位于 `publish-selectors.json`，可单独更新，无需改动音频和 MIDI 模块。

登录会话位于 `cache/publish-browser/平台/`，不会写入发布包、文稿或验证报告。
从原系统浏览器切换到助手内浏览器时，会一次性迁移助手专用会话；迁移文件在首次启动新浏览器时删除。
浏览器日志及各项完成状态保存在发布包内；在浏览器关闭后，本次辅助进程结束。
关闭助手不会自动发布，已打开的上传浏览器可以继续使用。

便携版中的 tests/ 使用合成音视频和本地网页验证上传及封面流程。
旧发布包仍可载入；要使用双比例适配，请重新生成发布包，再继续填写同一视频。

### 发布命令行

```powershell
# 首次登录，登录后手动关闭浏览器
& '.\dependencies\vocal2midi\python\python.exe' -B .\publish_browser.py --platform bilibili --login
& '.\dependencies\vocal2midi\python\python.exe' -B .\publish_browser.py --platform xiaohongshu --login

# content.json 为各平台 title/description，例如：
# {"bilibili":{"title":"【歌姬翻唱】歌名","description":"本家及STAFF..."}}
& '.\dependencies\vocal2midi\python\python.exe' -B .\publication.py --job '来源任务目录' --video '成品.mp4' --content-json '.\content.json'
# 默认使用本家原始封面。只有主动使用画面截图时，才加 --cover-mode frame --cover-seconds 20。

# 以上命令返回发布包目录，将其传给浏览器助手
& '.\dependencies\vocal2midi\python\python.exe' -B .\publish_browser.py --platform bilibili --bundle '发布包目录'
```

单独获取原始封面，不下载视频或运行 MIDI：

```powershell
& '.\dependencies\vocal2midi\python\python.exe' -B .\cover_art.py --source BV1UVtb6PENV --output '.\封面下载'
```

可输入 B站链接，已有封面会校验缓存；加 `--refresh` 可重新下载。第一次获取需要联网。
已查看你提供的 [Bilibili-Cover-Downloader](https://github.com/xjunz/Bilibili-Cover-Downloader)，它是安卓项目。
助手的封面功能由本地 Python 实现，直接读取 BV 资料中的封面地址，无需启动网页工具或安卓应用。

Playwright 1.63.0 及其运行库位于 `vendor`；浏览器程序位于 `dependencies/browser/chrome`，由 `publish_browser_executable` 指定。
上传不依赖系统安装的 Chrome 路径。登录资料仍位于助手自己的独立会话目录。

模型来源：[UVR 模型库](https://github.com/TRvlvr/model_repo/releases/tag/all_public_uvr_models)。
SpectraLayers 官方未公开直接调用 Unmix Song / Chorus 的命令行参数：
[会话参数](https://download.steinberg.net/downloads_software/SpectraLayers_13/help/Pro/_session_options.html)、
[启动参数](https://download.steinberg.net/downloads_software/SpectraLayers_13/help/Pro/_launch_options.html)。
它支持保存模块链并批处理文件，见 [官方批处理说明](https://download.steinberg.net/downloads_software/SpectraLayers_13/help/Pro/_batch_processing.html)；
本版尚未自动驱动这条软件流程。


## 依赖整合与检查

VocalFlow 目录内包含约 7.4 GiB 的必需依赖：

| 目录 | 内容 |
| --- | --- |
| `dependencies/vocal2midi/python` | Python、Qt、ONNX Runtime / DirectML、音频与 MIDI 运行库 |
| `dependencies/vocal2midi/experiments` | GAME、HubertFA、Qwen3-ASR、RMVPE、日语音素模型 |
| `dependencies/vocal2midi/application`、`inference`、`settings` | Vocal2Midi 调用代码和随助手保存的设置 |
| `dependencies/ffmpeg` | FFmpeg |
| `dependencies/models`、`models` | 人声/伴奏、主唱/和声分离模型及参数 |
| `dependencies/browser/chrome`、`vendor` | 浏览器程序、Playwright 与其驱动 |

原来的 JiJiDown、UVR、SpectraLayers、Vocal2Midi 安装保留在原位置。软件分轨模式仍由你在 SpectraLayers 导出 WAV，助手负责导入及后续提取；商业软件本体不包含在依赖包中。

双击 `检查依赖.bat` 可逐文件检查 SHA-256，结果写入 `依赖检查报告.json`。首次校验模型大文件需要一段时间。正常启动只检查关键路径与模型，不每次计算全部校验值。发现缺失或损坏时会保留日志和提示。

启动器使用自身目录定位 Python，支持空格和中文路径，不需要设置全局 PATH。复制助手时请复制整个 VocalFlow 文件夹；缓存、历史任务及专用登录会话都在其中。Windows 和显卡驱动仍由系统提供。

助手内的历史任务、最近任务与发布资料支持目录迁移后的路径定位。成品视频或外部导入 WAV 仍保留它们的原位置；移动这些外部输入后，应重新选择文件、准备发布包。依赖整合不会移动你的成品或改动历史素材。

模型分离和 MIDI 检查验证了结构、声部、采样数和时间轴；歌词及音准仍需试听核对。调音、mixdown 对齐和视频合成继续由人工完成，最终发布继续由你点击。
