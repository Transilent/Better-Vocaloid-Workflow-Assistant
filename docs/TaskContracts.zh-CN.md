# 任务状态与文件记录

[English](TaskContracts.en.md)

助手分别记录程序的处理进度和你在编辑器中完成的工作。生成 MIDI 后，仍需要调音、渲染和准备发布；这些环节不再混用一个“已完成”状态。

## 各记录的职责

| 记录 | 内容 |
| --- | --- |
| `request.json` | 任务实际使用的处理选项；未启用的导出偏好另行保存。继续任务不会改写原请求。 |
| `status.json` | 本轮执行计划、当前步骤、用时，以及每个步骤的成功、失败或停止状态。 |
| 各模块的处理回执 | 推理、工程和音频导出的输入签名及文件哈希，继续决定缓存是否可复用。每个声部、每种格式分别提交结果。 |
| `artifacts.json` | 有版本号的文件清单，记录用途、SHA-256、生成环节和依赖版本，可从处理回执重建。 |
| `task.json` | 任务名、明确登记的调音工程／Mixdown／成品视频，以及当前发布资料。重建清单不会丢失这些登记。 |

文件清单补充现有回执的职责。它不作为程序更新清单，也不赋予删除任意文件的权限。

## 检查文件并继续

在“任务与结果”中选中任务，打开“文件与下一步”。检查在后台完成，能区分校验通过、文件缺失、已修改、无法读取及依赖变化。文件被修改后，检查不会把当前内容自动认作原始结果；只有实际重新生成或明确登记，才会接受新版本。

完成调音后，可以登记修改后的工程和导出的 Mixdown，再进入可选的视频合成工具；已有成品时，也可以直接登记视频并进入发布工作流。文件保留在原位置。登记新的版本后，依赖旧版本的后续文件会提示核对，不会被覆盖。

下一步提示涵盖处理、重试、调音、Mixdown、成品、发布准备和创作中心核对。**最终发布仍由你手动确认。** 上传助手只记录平台上的准备状态，不会自行认定作品已经发布。

## 续跑与恢复

上游重新处理前，先将后续记录标记为失效。某个声部或格式失败，不会删除其他已提交结果的记录；重试时继续使用现有签名判断哪些内容可以复用。

旧任务在续跑或检查时，按已有回执补建清单。旧文件没有哈希回执时，以迁移当时的内容为基准，无法追溯迁移前是否被修改。重建清单会备份原清单，不修改音视频和工程。未知版本、损坏记录和越过自动产物目录边界的路径会被拒绝。

任务列表只做轻量检查；完整内容校验请打开“文件与下一步”。外部编辑器在检查后仍可能再次保存，所以真正使用输入的模块还会核对其内容。

## 缓存清理

清理前会重新检查任务引用。缓存或临时目录中仍有已登记的 Mixdown、工程、校准输入或其他有效依赖时，会受到保护，并显示引用它的任务。外部引用只读，不会扩大可删除范围。其他任务仍引用某个任务内的文件时，需先更换或取消引用，才能删除该任务。

取消登记不会删除原文件。只有明确执行删除任务才会删除其文件。原有模型、登录会话和发布资料的清理边界继续生效。
