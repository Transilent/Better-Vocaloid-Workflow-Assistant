# 用人工工程评估音符识别

[English](NoteEvaluation.en.md) | [简体中文](NoteEvaluation.zh-CN.md)

人工 SVP 可以帮助定位漏转音、音节合并、错音和边界问题。本流程把它作为乐谱参考，不把参考音符或歌词交给识别器，也不复制为识别结果。

## 准备对照

选取实际发声的主旋律，包含被引用的音符组实例，使用工程速度表将位置换成秒。记录轨道、固定音频偏移、移调和输入哈希，先确认音频版本；短版、合集、另一版翻唱可能造成误导。

先固定音频片段和分离结果，再比较算法。裁切边缘的不完整音符、明确用于呼吸或静音的标记不参与打分，排除项单独保留；正常延音和短演唱音符仍保留。不能看到候选结果后再挑区间或调整对齐，使候选占优。

评估自动路线时，参考歌词留空。保留模型原始音符、实测音高、音节对齐及最终结果，在这些固定输入上重放后处理，排除模型随机变化的干扰；还需要实际完整运行工作进程，检查集成、取消、缓存和输出格式。

## 指标

源码内研究工具读取参考 JSON 的 `notes` 列表，每项含秒数 `onset`、`offset` 和 MIDI 音高 `pitch`，可选 `lyric`，其他字段用于来源记录。

```powershell
dependencies\vocal2midi\python\python.exe -B tools\research\note_benchmark.py work\reference.json work\prediction.mid work\note-metrics.json
```

音符一对一匹配，先最大化有效配对数量，再比较时间距离；重复预测不能重复得分。报告分别按起音误差 50 ms、100 ms，且音高相差不超过半音，计算精确率、召回率及 F1。带收尾的指标还要求终点误差不超过 50 ms 与参考时长 20% 中的较大值。读取 MIDI 时遵循速度变化，报告保留漏音、多余音符、起音相近但音高错误的项目及边界差异。

这些指标衡量与所选乐谱的吻合。人工工程可能用两个音符记录倚音，也可能用一个音符加曲线；乐谱起点也可能早于实际元音。因此，记谱不同不自动等于听感错误，需要同时报告严格、宽松容差，并结合波形及音高线检查。

## 当前有界修复

Vocal2Midi 2.0 的音符校验现独立于编辑器工程和音高线导出开关。关闭曲线导出后，仍会移除工程的显式调音数据。原有识别和音高权重保留。

短而稳定的音高变化可提示转音被合并。开发中曾尝试只根据曲线补拆，但它也拆开了句尾弯音，因此没有采用。现在新增短转音边界还必须由局部 GAME 推理确认位置和两侧音高。工作进程只使用本次音频及识别对齐，不依赖参考工程集合。原有长转音处理保留，平滑周期性宽颤音不会据此增加音符，明确阶梯式变化仍可处理；实测连续音高保留。

局部复查与坍缩音节恢复共用每声部 16 个窗口、24 秒候选音频预算，复用现有模型。无法确认或可选推理失败时保留原音符，取消操作会继续向上传递，尝试写入质量回执。这项保守策略仍会漏掉 GAME 无法确认的一些真实短倚音。

局部确认也会比较 GAME 原始连续音高与实测中心。先将两者取整可能掩盖接近半音的差异；半音边界附近的滑音不足以支持新增音符。新候选的 GAME 中心须距整数音高不超过 0.3 半音，且与局部实测中心相差不超过 0.45 半音。这些条件仅用于判断是否新增音符，保留的连续音高线不受影响。

少量开发样例只能验证具体问题，不能建立普遍准确率。未通过的候选和每首歌的评估角色应保留；已经用于改规则的歌曲，不能继续称为未见过的留出测试。中日文需要分别实测，保留已有 ASR 路线不代表两种语言的准确率相同。
