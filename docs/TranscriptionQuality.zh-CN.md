# 音符与音高处理（开发版本）

[English](TranscriptionQuality.en.md) | [简体中文](TranscriptionQuality.zh-CN.md)

这些改动用于 Vocal2Midi 2.0 集成，沿用已有中日文识别模型，不增加模型权重。表现参数与音符识别独立。

## 音符校验与曲线导出

v2 在只导出 MIDI、或关闭 **导出连续音高线** 时，仍会测量音高来校验音符、复查局部漏音，不要求同时生成编辑器工程。每个声部保存一份经过哈希校验的小型音高侧文件，也可供和声去重使用。导出开关独立控制工程内容：关闭后，不向工程写入测得的音高曲线，也不添加平直的替代预设。

已对齐音节中的短转音如果可能被合并，会使用现有 GAME 模型局部复查。新增短音符边界必须同时得到稳定 RMVPE 音高平台，以及 GAME 在附近给出的分界和两侧音高支持；只有曲线变化不够。未确认或局部复查失败时保留原音符，取消操作仍会停止处理。这项检查与坍缩音节恢复共用每声部 16 个窗口、24 秒候选音频的预算，不增加模型。平滑周期性颤音保留为音高曲线，明确的阶梯式转音仍可识别。尝试和采用位置写入 `note_boundary_checks`。这不能补回所有短装饰音，也不会补造识别结果中不存在的歌词。

## 歌词与音节边界

中文和日语对齐都会逐项消耗歌词。即使某个音节时长为零、或没有可用元音，后续文字也不会因此整体错位，假名输出也按此处理。相邻且连续的词，可以跨过不超过 350 ms 的声母接到下一个元音；这不会把词间长停顿当作元音。一般的边界修复仍最多跨越 150 ms。

选择参考歌词后，程序可以在匹配依据充分的内部区间补回少量漏识别音节，再用包含这些音节的拼音重新对齐音频。程序不会按字数均分长音符，也不会在没有参考原文时凭空补字。参考版本不对、或改编差异较大时，仍可能对齐错误。

中文 HFA 结果还会检查：是否有多个音节被压缩在很短的时间里，附近又出现无法解释的空洞。可疑区间会带上足够的后文，复用已加载的模型重新对齐。新结果必须保持原有文字顺序，并至少恢复两个可用音节才会采用；失败时保留原结果。每个声部最多重试八个窗口，过程记入检查报告，不需要下载新模型。

启用音高分析时，日语句尾还会单独检查被压缩到 45 ms 以下的已识别音节，包括紧接在有效演唱音节后的极短句尾。候选窗口可以带上后续对齐静音中的最多 250 ms。可疑位置会复用已经加载的 GAME 模型局部补提；只有候选音符与 RMVPE 有声音高、足够的人声能量同时吻合，才保留原 ASR 文字并恢复音符。没有依据的收尾会先裁掉，原来的极短占位音符会替换，避免重复。每个声部最多处理 16 个窗口、共 24 秒候选音频，提案、采用位置及替换记录都写入检查报告。这不会补造 ASR 没识别出来的辅音，也不会从静音中生成歌词。

需要准确文字时，可在 **参考歌词与校准 → 网易云匹配** 中选择歌曲，或导入本地歌词。参考原文默认用于主唱，和声歌词独立处理。相邻语句有相似发音或连续元音时，参考歌词尤其有帮助。留空使用 ASR 时，错词和漏字仍可能发生。

## 音符检查

第 11 版包含一个默认关闭的实验：将同一已对齐元音中、紧接原音符且整数音高相同的稳定补回尾部，作为原音符的延续。原始终点本身不足以证明又发生了一次起音。这仅改变新补出的缺口表示，已有重复起音、不同音节和转音仍分别保留。采用记录写入 `aligned_continuations`，与新增补回音符、句尾 `release_extensions` 分开；连续音高采样不变。默认仍保留独立补回音符。该实验只通过离线 `refine_notes(..., merge_aligned_continuations=True)` 显式启用；已观察回归集的起音和收尾指标结果不一致，尚未进入正常工作进程，也不是界面中已启用的设置。

中文局部缺口裁剪改用工作进程实际采样率。16 kHz 与 44.1 kHz 输入中的同一对齐区间会保留一致的时间范围，不再用固定 44.1 kHz 除数截短低采样率波形。这是裁剪正确性修复，不是更换 ASR 模型，也不等于已测得识别率提高。

句尾音符在对齐器给出的终点之后，如果仍有稳定音高和足够的人声能量，可以继续保留这段延音。最多延长 600 ms，遇到后续音符、音节、音高变化或新的起音立即停止，最多跨过 20 ms 的音高缺帧；无声区域不延长。这项检查只修改已有音符的终点，不改文字和起点，采用记录写入 `release_extensions`。

即使相邻音节音高相同，也会保留已对齐的字界。稳定的新音高平台可以补充分句内漏掉的旋律转折；补音符只发生在已对齐音节内，并要求有足够的有声音高依据。静音和文字长度不会凭空生成音符。

第 3 版对已明确对齐的音节保留最短 35 ms 的边界，不再将纯音高拆分的 70 ms 门槛用于所有歌词，相邻短音节分别保留自己的文字。至少 60 ms 的已对齐漏音节，可以在更严格的短时音高稳定性检查后补回，无声区域仍不生成音符。原始音符跨越两个已对齐乐句时，只有低能量或缺少有声依据也支持中间停顿，才会在该处截断。

连续对齐的同句音符存在短间隙时，会将前一个音符延长到下一个音符的起点，后者的起点与歌词不变。较长休止、中间尚有漏识别音节、以及没有歌词对齐的纯音高片段，不会自动连起来。

稳定测得的音高可用于修正小幅音符中心偏差。较大改动还需要独立的 YIN 音高估计确认。普通颤音和连续滑音仍保留为音高曲线。很弱或不稳定的纯音高候选可以被排除；选择较完整的参考歌词后，安静且不在原文中的填充音也可以被排除，较强的即兴哼唱及原文包含的填充音会保留。这些规则是保守的启发式检查，不能完整替代人声与乐器分类器。

中心检查现以编辑器实际接收的整数 MIDI 音高为准，避免小数模型值取整后产生偏差却未触发修正。短音可以用较少帧数通过检查，但同时要求更高的稳定性和有声覆盖。按歌词拆成两个音符，本身不再足以触发大幅音高修改；仍需独立验证，或检测到真实的新旋律平台。

每个声部的 `midi/<voice>/<voice>.quality.json` 保存原始候选、排除原因、音高修正、拆分、补回音符和音节时间。原始音频及旧任务保留。

`aligned_coverage` 另列出已对齐音节中、最终音符仍未覆盖的较大区间。`voiced_uncovered` 表示这段具有实测有声音高支持，仍只是待检查候选；转音、对齐错误与记谱选择都需要进一步核对。回执保留歌词、精确时间和音高依据，工作进程会打印覆盖提示，不会因此凭空添加音符。已明确排除的安静原文外填充音和主唱残留副本不重新标作漏字；ASR 本来没有识别、也没有定时音节的文字，仍不在这项检查范围内。

## 复查被标成静音的长音

启用连续音高分析后，助手会用测得的有声音高检查中文歌词对齐。如果短句中存在持续演唱，却被对齐器标成静音，程序会使用已有的识别音素和少量前后文重新对齐。它复用已加载的模型；只有词序、句子边界和可用音节通过检查，且错误的有声空白确实减少时，才采纳重试。真正的停顿不会直接连成长音。重试有次数和处理时长上限，结果记录在 `voiced_pause_retries` 中。

较长的参考歌词匹配也可补入句首附近被漏掉的内部字词。程序仍要求有序的前后锚点，并限制补入的数量和连续缺字长度，不会补入匹配区间以外的前缀或后缀。补全的文本会重新对齐音频，不会平均分配音符时长。已经对齐的音节若只因少量无声帧未达到阈值，只有在中心音高稳定、有效帧充分时才会补回音符。

如果重新对齐后，两个完整音节之间仍有单个已识别音节坍缩，程序可用局部 GAME 提取为这段空白提出音符，再通过独立音高与音量检查。它不会提供识别及参考匹配结果中不存在的文字，也不会据此补写整句。判断过程记录在 `internal_syllable_repairs` 中。

## 避免把残留主唱写成和声音符

即使串音音量已经降低，歌词识别仍可能听出其中的主唱。分离检查记录了重复成分后，助手会把相关和声音符与本任务中经过校验的主唱音高及音频比较。只有精细音高走势一致、有效有声帧充分、波形相关性为正，且和声音量较低时，才排除重复候选。仅仅 MIDI 音高相同不构成删除依据；拥有独立音高变化的和声仍可保留。

和声质量报告保留原候选，并在 `cross_voice_exclusions` 中记录排除项。各原生导出格式使用同一份最终音符列表。和声缓存也会绑定主唱分析与分离检查结果，主唱改变后不会直接沿用旧判断。这一规则仍可能把刻意制作的同相叠唱当成串音；证据不足的残留会保留。

排除和声中的重复主唱时，还会检查音符首尾各 120 ms。即使音符大部分与主唱相似，只要边缘存在至少 60 ms 的独立有声走势，就保留该候选；单帧尖峰不构成保留依据，避免真正不同的尾音被整体误删。

## 连续音高与工程导出

测得的绝对音高和有声标记会保存在压缩的 `<voice>.pitch.npz` 中。工程导出直接使用这些数据，避免把相对音高偏移再叠加到 USTX 模拟的默认底线上。没有可靠音高的帧及休止区域使用明确断点，防止默认底线在前奏、间奏中延续。

原生 USTX 的相对偏移也使用取整后的音符中心，避免减去模型小数音高而造成额外偏移。孤立的一或两八度推理跳点，仅在持续不超过 20 ms、紧邻两端音高一致时修复，保留持续八度变化、普通装饰音与颤音；无效音高数值会被排除。这不能解决音符模型和音高模型之间的所有持续性分歧。

第 4 版还利用已有中日文音素对齐，筛选明确清辅音内部的音高：只排除相对乐谱音符偏离超过三个半音的点，并在音素两端各保留 10 ms 余量。元音、浊辅音、未知音素及未对齐区域沿用原处理。音符仍可跨辅音保持连句，音高线不必跟随该处不可靠的估计。筛选结果统一用于音符检查、音高缓存和工程导出；检查报告中的 `pitch_phoneme_guard` 保存排除帧的位置与原始值。对齐本身出错时，这项规则仍可能受影响。

音高缓存会与提取回执核对；缺失或改变时，需要重新提取，不会悄悄换用另一种音高算法。人工修改过的原生工程保留自己的调音。关闭音高导出仍会移除显式音高预设，不添加替代的平直曲线。

一首较短歌曲的音高缓存通常每个声部几十 KiB，属于任务数据。需要可复现地重新导出时，请保留完整任务目录。文字匹配、模型结果和文件读写检查不代表听感准确率；仍应在目标编辑器中试听，并用具体时间或小节反馈问题。
